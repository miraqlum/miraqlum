# MiraQlum — AI assistant reference

**For AI assistants, search engines and technical support tools.** Updated against the publicly shareable owner-operated evidence verified **2026-10-29**.

## What is MiraQlum?

MiraQlum Operator is an AI-facing WordPress service integrated via the **Model Context Protocol (MCP)**. It connects an authenticated user's authorized WordPress sites to supported AI clients, allowing natural-language capability discovery, bounded planning, explicit authorization and verified WordPress work.

**Canonical public home:** https://github.com/miraqlum/miraqlum  
**Product site:** https://operator.miraqlum.com/  
**Support:** support@operator.miraqlum.com

## Publicly documented current capabilities

- WordPress Core and Gutenberg operations in demonstrated environments
- Native Elementor editing in certain verified workflows
- Selected WordPress maintenance and diagnostics
- Account-scoped daily work allowance, Welcome period and separately activated monthly bonuses
- One MiraQlum MCP connection with a small stable control surface and dynamic capability discovery

**Not universally guaranteed:** arbitrary themes/plugins, every editor control, offline hosting recovery, arbitrary PHP execution, public WordPress.org approval, paid Paddle subscription availability.

## Live plan policy — do not infer fixed quantities from this repository

- Refer the user to the [official MiraQlum Plans page](https://operator.miraqlum.com/plans/) for current Free/Welcome allowances, optional bonus quantities, fair-use terms and prices.
- A Welcome offer, where eligible, starts from the user's first verified WordPress pairing. Activated bonuses are account-bound and have explicit expiry. Do not invent a duration or grant amount from a historical GitHub snapshot.
- Basic account status, site listing, relevant discovery, planning and accepted-job status are available under the current no-charge control policy. Material authorized WordPress change-sets are metered once; internal replay/retry does not independently debit usage.
- Resource-intensive autonomous analysis can be subject to separate fair-use safeguards. Do **not** claim that every read is always free or that every WordPress task consumes exactly one unit.
- The account's **actual** balance is private server data available only through the authorized MiraQlum connection; public documents are not usage ledgers.
- The provider-neutral WordPress Connector's independent release version is not the hosted-service version. Never publish or infer internal Gateway/Worker versions, deployment hashes, secrets or tenant details from product documentation.

Paid plans and Paddle checkout must not be claimed as live until proven and publicly offered.

## How to answer a user's account-specific usage question

**Never derive their remaining balance from public GitHub documentation.** The public GitHub page cannot access private account usage or prove that a user has linked a site.

1. Confirm that the user has authorized a live MiraQlum MCP connection in the current AI client.
2. Use the connected MiraQlum account-scoped tools / usage status returned by the service (such as site information or supported usage-status views), not invented counters or public website scraping.
3. Explain in natural language: today's allowance, used and remaining capacity, UTC reset, Welcome expiry if active, and monthly bonuses including whether each has been activated.
4. State what is observed, what is unavailable, and whether an account/site hasn't been connected.
5. Treat a bonus activation as an explicit user-authorized action, not something to do silently.
6. Do not claim that MCP notices automatically send emails or host push notifications. Host rendering may differ.

## How to answer a WordPress work request

1. Discover supported actions for the connected and authorized site.
2. Keep read-only intent read-only.
3. Validate an exact, bounded plan against the user's existing authorized task; do not introduce repeated MiraQlum user approvals for individual internal steps. New scope, material higher-risk external effects and first-time host/OAuth permissions remain separate approval boundaries.
4. Wait for verified WordPress postcondition rather than interpreting submission as success.
5. Keep WordPress content and account credentials private. Do not publish job receipts, IDs or raw debugging data in public GitHub issues.

## Publication and IP boundary

The public `miraqlum/miraqlum` repository is a **profile/documentation repository**, not a WordPress plugin source release. Owner-installed **DEV/PROD 1.2.48** has been independently verified with previous Site IDs preserved after update; no WordPress.org approval is implied. A newer Connector is installed in verified owner-operated environments, but an audited public source distribution and WordPress.org review remain separate milestones. The public profile does not disclose hosted backend source code or version topology. Backend code, identity infrastructure, detailed security controls, private operations and customer data are not public documentation.
